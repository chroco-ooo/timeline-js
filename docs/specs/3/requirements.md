# Issue #3 タイムラインのデザイン向上 — Requirements

## 位置付け

- 対象Issue: [#3 タイムラインのデザイン向上](https://github.com/chroco-ooo/timeline-js/issues/3)
- 本書はIssue #3に適用する要件を整理する。
- 具体的な寸法、色、マーカー形状、DOM構造は `design.md` で定義する。
- 実装手順と検証順は `tasks.md` と `test-plan.md` で定義する。

## 背景と目的

Timeline JSは横型と縦型のタイムラインを提供している。現在の縦型表示は、中央の時間軸、年区切り、左右交互のイベントカード、画像、日付、タイトル、説明文を表示できる。横型表示は年月軸上のイベントとイベント間の関係を表示できる。

一方、カード、影、枠線、破線、引用符、イベント固有色などの視覚要素が重なり、時間の流れと情報の優先順位が分かりにくくなる場合がある。また、カテゴリー、重要イベント、現在位置を表現する共通仕様がない。

本Issueでは既存構造を活かし、タイムラインを「カードUIの集合」ではなく「時間の流れを中心に情報を読むUI」として整理する。大規模なレイアウト変更や描画エンジンの刷新は行わない。

## 対象ユーザー

- Timeline JSをWebサイトへ組み込む開発者
- 会社、サービス、団体、プロジェクトの沿革を掲載する利用者
- 活動履歴やポートフォリオを掲載する利用者
- PCまたはスマートフォンでタイムラインを閲覧するエンドユーザー

## 基本方針

- 装飾を増やさず、余白、文字、線、色を整理する。
- 年、イベントタイトル、日付、本文、補助情報の優先順位を明確にする。
- 時間軸を視覚上の中心として扱う。
- 横型と縦型で共通する色、文字、線、マーカー、操作状態を用いる。
- 色数を抑え、イベント固有色は限定された箇所に用いる。
- 過度な影、角丸、枠線、hover時の浮き上がりを避ける。
- PCとスマートフォンの双方で可読性と操作性を維持する。
- 既存ライブラリの組み込み先へ影響を与えないため、コンストラクターオプションと `projects` / `links` のパラメータは追加・変更しない。
- 既存データと公開APIの後方互換性を維持する。

## 第一段階の必須要件

### R1. 年区切りを強調する

- 縦型の年をイベントカードより上位の見出しとして表示する。
- 現在のピル型表現を、大きめの年表示と細い横線を基本とする簡素な表現へ変更する。
- 年の周囲に強い背景色、枠線、影を使用しない。
- 年の変更地点をスクロール中に判別できる。
- PCとスマートフォンの双方で表示できる。

年区切りを非表示にするオプションは追加しない。

### R2. 縦軸を実線化する

- 縦型の時間軸を一本の連続した実線として表示する。
- 線は1〜2px程度を候補とし、イベントアクセントと分離した低彩度色を用いる。
- イベントマーカーが時間軸上の出来事であることを判別できる。
- 線自体が年やイベントタイトルより強く見えないようにする。

線は1pxの実線を基本とし、グラデーションは使用しない。色は `design.md` の時間軸トークンを使用する。

### R3. カテゴリーチップを追加する（後続Issueへ延期）

既存projectにはカテゴリー情報がない。既存値からカテゴリーを推測せず、パラメータ変更を検討できる後続Issueへ延期する。

### R4. milestone表示を追加する（後続Issueへ延期）

既存projectには重要度情報がない。`color` やevent名から重要度を推測せず、パラメータ変更を検討できる後続Issueへ延期する。

### R5. 現在位置「NOW」を追加する

- 現在日時がタイムラインの表示期間内の場合だけ、縦型にNOWを表示する。
- NOWにより過去と未来の境界を判別できる。
- 小さなラベルと時間軸を横切る線またはマーカーを候補とする。
- イベント日時と現在日時が近い場合も、イベントカードや操作要素を隠さない。
- 表示期間外ではNOWの要素や不自然な余白を表示しない。
- PCとスマートフォンの双方で表示できる。
- 横型の既存Today表示とのデザイン言語を可能な範囲で統一する。

新しい基準日時パラメータは追加せず、既存の横型Today表示と同様にシステム日時を使用する。

### R6. サムネイルをカード上部へ表示する

- 画像付きイベントはPCとスマートフォンの双方でサムネイルをカード上部へ全幅表示する。
- サムネイルの下に本文を配置する。
- 画像なしイベントでは本文が不自然に狭くならず、不要な画像領域を残さない。
- PCとスマートフォンで情報の有無や意味が変わらないようにする。
- 極端なアスペクト比の画像でもカード高が過度に変化しない。

画像は4:3を基本として `object-fit: cover` でトリミングする。

## 第一段階に付随するデザイン調整

必須要件を自然に成立させる範囲で、以下を調整する。

- カードのbox-shadow、枠線、角丸、hover時の移動量を弱める。
- 年、イベントタイトル、日付、本文、補助情報の順に視覚階層を整理する。
- 引用文ではない説明文から大きな引用符装飾を削除または簡素化する。
- ベース背景、主文字、副文字、境界線、主アクセントを基本とするカラーパレットへ整理する。
- event固有色はマーカーやリンクなどの限定された箇所で使用する。
- 横型では大規模な構造変更を行わず、色、文字、マーカー、現在位置、hover / focus、余白、線の太さを縦型と可能な範囲で統一する。

## 維持する既存仕様

- 横型・縦型タイムラインとその切り替え
- `projects` によるタイムライン生成
- 開始日、終了日、イベント日時、タイトル、説明、画像の表示
- `onProjectClick` とlinkモード
- 横型のイベント間リンク
- 同一日時イベントの入力順
- PC・スマートフォン向けレスポンシブ表示
- 既存形式の `projects` データ
- キーボードフォーカスを含む既存アクセシビリティ

## 対象外

- タイムライン描画エンジンの全面刷新
- React、Vue等のフレームワークへの移行
- 横型タイムラインの全面再設計
- ドラッグ編集、画面上のデータ編集、管理画面
- 認証、権限、イベント単位のアクセス制御
- 検索、絞り込み、ズーム
- 複雑なアニメーション
- テーマエディター、WYSIWYG編集
- DB、HTTP API、外部サービス連携の追加

外部URLや画像URLのアクセス制御はTimeline JSの責務外とする。ただし、安全なDOM出力と既存のリンク属性は維持する。

## 受け入れ条件

- [x] 縦型で年区切りがカードより上位の見出しとして表示される。
- [x] 縦型の時間軸が控えめな実線として表示される。
- [x] 現在日時が表示期間内の場合だけNOWを確認できる。
- [x] NOWとイベントが同時刻または近接しても、情報や操作要素を隠さない。
- [x] 画像付きeventのサムネイルがカード上部へ全幅表示され、画像なしeventも自然に表示される。
- [x] スマートフォンでは読みやすい縦積みになる。
- [x] 年、タイトル、日付、本文、補助情報の視覚階層を判別できる。
- [x] カードの影、枠、角丸、引用符、色数が基本方針に沿って整理される。
- [x] 横型・縦型に共通する色、文字、マーカー、操作状態に統一感がある。
- [x] 既存データを変更せずデモを描画できる。
- [x] 横型・縦型の切り替え、クリック、リンク、接続線、同一日時の並び順が回帰していない。
- [x] PCとスマートフォンで重なり、意図しない切れ、操作不能がない。
- [x] キーボードフォーカス等の既存アクセシビリティを損なわない。
- [x] README、画面仕様、JavaScript API仕様が最終実装と同期している。

主観的な「従来より良い」だけを判定基準にせず、同一データ、同一viewport、Chrome、ブラウザ倍率100%で撮影したbefore / after画像を受け入れ時の比較基準にする。代表画像は幅1440pxの縦型表示とする。

## 確認観点

### 通常系

- 画像を持つ既存形式のevent
- 画像を持たない既存形式のevent
- 横型と縦型の相互切り替え
- 現在日時を含む表示期間

### 異常系・境界値

- 現在日時が開始前、終了後、イベントと完全一致する場合
- 同日または同時刻に多数のeventがある場合
- 非常に長いタイトル・説明
- 縦長、横長、読み込み失敗、未指定の画像
- 単年、短期間、event 1件、event 0件
- 640px前後と狭い画面幅
- 長期間の横型表示と仮想スクロール

### 実行方法

```powershell
node --check timeline.js
python -m http.server 8000
```

ブラウザで横型・縦型、PC幅・640px以下、クリック・リンク、キーボードフォーカス、コンソールerror / warningを確認する。変更前後のスクリーンショットをPRに添付する。

## 確定事項

1. NOWは同時刻event群の直後へ置き、event群の入力順を維持する。
2. NOWの年にeventがない場合も新しい年chapterは生成せず、NOWだけを正しい時系列位置へ置く。
3. 画像付きカードは全画面幅でサムネイル、本文の順に縦積みし、画像4:3、`object-fit: cover`を基本とする。
4. 既存の640pxレスポンシブ境界は余白、軸、文字サイズの調整に使用する。
5. 長いタイトルと説明は省略せず、折り返して全文表示する。
6. 既存CSS classは削除・改名しない。上部サムネイル表示に必要な補助classは追加できるが、見た目とDOM直接子関係の完全互換は保証しない。
7. 新デザインを既定にし、旧デザインとの切り替えオプションは追加しない。
8. 正式な確認対象はChrome、Edge、Firefox、Safariの最新2メジャーバージョンとする。
9. アクセシビリティはWCAG 2.2 AAを目標とし、focus可視性、キーボード操作、文字と主要UIのコントラストを受け入れ対象にする。
10. NOWは操作要素にせず、`role="separator"` と `aria-label="現在"` で読み上げ可能にする。
11. 横型のラベル「今日」と縦型のラベル「NOW」は、それぞれの意味を維持する。
12. `thumbnail.png` は本Issueでは差し替えず、現行画像を維持する。

カテゴリー、milestone、基準日時の外部指定は本Issueの未決事項ではなく、パラメータ変更を許容する後続Issueの検討事項とする。

## 変更範囲候補

- `timeline.js`: システム日時によるNOWと、既存入力から生成する必要最小限のDOM・class・ARIA属性
- `css/timeline.css`: 縦型を中心とした表示とレスポンシブ調整
- `index.html`: 既存パラメータだけを使った表示・境界値確認用デモデータ
- `README.md`: 公開オプション、project項目、デモ画像
- `docs/api-spec.md`: 公開APIに変更がないことの確認。原則変更不要
- `docs/screen-spec.md`: 表示要素、状態、レスポンシブ仕様
- `docs/testing-policy.md`: 追加した境界値と手動確認

`.github/workflows/static.yml`、依存関係、DB、デプロイ方式は変更対象外とする。
